# 자유 에세이 회고

사용자가 승인한 자유 에세이 방식과 기존 회고 입력 한도 확장을 구현한다.

- 작성 방식에 `자유 에세이`를 추가한다. 제목은 선택(최대 150자), 본문은 필수(앞뒤 공백을 제외하고 최소 100자, 전체 최대 3,000자)다.
- 입력 안내는 이번 회고 기간의 경험과 그 경험에 대한 생각·느낀 점을 포함하도록 설명한다. 감정 점수·이유와 시간 기록 이미지는 기존처럼 선택이다.
- 기존 항목별 회고와 감정 이유는 최대 1,000자로 늘린다. AI 정리와 폴백, 관리자 수정도 같은 한도를 사용한다. 질문별 답변 입력 한도는 유지한다.
- 기존 `retrospectives`에 `content_format`(`structured` 기본값 또는 `essay`), `essay_title`, `essay_body`를 새 마이그레이션으로 추가한다. 기존 네 항목의 NOT NULL을 보존하고 에세이에서는 빈 문자열을 저장한다.
- 직접·질문형의 기존 기록은 `structured`로 취급한다. 에세이 원문은 별도 컬럼에 저장하고 Slack에서 일반 텍스트로 표시한다.
- DB 저장 후 Slack 게시, 게시 실패 처리, 미게시 행 재사용, 운영 회차의 사용자·회차 UNIQUE 및 테스트 회차 예외를 유지한다. 미게시 행에서 방식이 바뀌면 이전 본문을 지운다.
- 게시, 내 회고 상세, 관리자 미리보기·수정, 관리자 웹 목록·상세, 워드클라우드를 형식에 맞게 연결한다. 제출 집계와 리마인더에는 기존 회고와 동일하게 반영한다.
- 운영 데이터·토큰·인증·볼륨을 보존하고 테스트는 네트워크가 차단된 별도 컨테이너와 임시 SQLite만 사용한다. 운영 스키마를 적용하기 전에는 DB 백업을 검증한다.

## 선택한 접근

기존 테이블에 형식과 본문을 추가한다. 별도 회고 테이블은 제출 집계와 중복 방지 경로가 갈라지고, 기존 항목에 에세이를 넣는 방식은 본문 의미와 표시가 어긋나므로 채택하지 않는다. 이는 앞선 대화에서 설명한 구조를 따른다.

이번 요청의 구현·검증을 우선하며, 별도 지시 없는 커밋·푸시는 실행하지 않는다.
