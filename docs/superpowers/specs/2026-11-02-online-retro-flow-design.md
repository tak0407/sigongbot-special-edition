# 온라인 회고 입장·이끌이·작성 완료

## 사용자 결정

- 별도 출석 버튼을 없애고 모든 `모임 입장` 버튼 클릭을 출석으로 기록한다.
- 모임 시작 시각까지 출석한 사람 중 이끌이 한 명을 무작위로 정한다.
- 이끌이는 진행을 맡지만 공유·인증샷 단계 버튼은 출석한 누구나 사용한다.
- 출석자 전원이 회고를 제출하면 자동으로 모두 작성 완료했다고 안내한다.

## 구현 방식과 선택 이유

기존 Slack URL 버튼에 회차·팀 값을 함께 넣고 상호작용에서 출석을 기록한다.
Meet 입장 자체를 감시하는 방식은 필요하지 않다. 이전 메시지의 별도 출석 버튼은
호환용으로 처리하되 새 메시지에서는 생성하지 않는다.

이끌이는 SQLite의 모임별 레코드로 저장한다. 메모리에서만 추첨하면 재시작이나
Slack 공지 재시도 때 사람이 바뀌므로 사용하지 않는다. 참석 기준은 투표가 아니라
입장 클릭으로 기록된 출석이다. 변경된 모임 시작 시각은 별도 추첨으로 취급한다.

전원 제출은 출석자 집합이 비어 있지 않고 전원이 실제 Slack 게시까지 성공한
회고 기록을 가졌을 때 판정한다. 제출 직후 확인하며 60초 스케줄러도 재확인한다.
전원 완료 공지에는 기존 공유 시작 버튼을 제공한다. 공유는 자동으로 시작하지 않는다.

## 구현자가 정한 경계 처리

- 시작 시각에 출석자가 없으면 입장자가 생긴 뒤 현재 출석자 중 추첨한다.
- 시작 전에 추첨하거나 작성 완료 공지를 보내지 않는다.
- 전원 완료 안내는 한 번만 보낸다. 먼저 보냈으면 시간 종료 안내를 생략한다.
  시간 종료 안내 이후 전원이 제출하면 완료 안내를 추가로 보낼 수 있다.
- 공유·인증샷 단계에 진입한 뒤에는 작성 종료·완료 안내를 추가하지 않는다.
- 같은 사용자의 반복 입장은 최초 출석 시각을 보존한다. 다른 팀과 너무 이른
  클릭은 기존 기준대로 출석 기록에서 제외한다.
- 기존 URL 버튼의 값이 없으면 원래 메시지의 URL로 모임을 유일하게 찾을 때만
  출석을 기록한다. 모호한 경우 최신 공지 이용을 안내한다.

## 운영 제약

운영 비밀값·DB·인증정보를 Git에 넣지 않는다. 새 스키마는 새 마이그레이션으로만
추가하고 운영 적용 전 백업을 검증한다. 다른 작업이 19번 마이그레이션을 작성 중이므로
이 기능은 20번을 사용한다. 현재 작업에서는 운영 배포를 실행하지 않는다.
